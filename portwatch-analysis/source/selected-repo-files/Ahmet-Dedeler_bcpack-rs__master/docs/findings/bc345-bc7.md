# Findings: block rebuild for BC3, BC4, BC5 and BC7

2026-11-24 (updated 2026-11-25 after landing `bc5-bc7` on `master`). Numbers below are on retail Xbox Series texture
stores read in place (46 main + 11 content-pack stores); no game bytes are committed.

## What is in the tree

- `src/format.rs`: modes, lane widths, the two references of a record, the dictionary addressing.
- `src/bcn.rs`: BC3 / BC4 / BC5 rebuild (endpoint and index states summed against two references).
- `src/bc7.rs`: BC7 rebuild (8-bit top-aligned endpoint state, 4-bit top-aligned index state, control codes), block
  pack and unpack.
- `data/bc3.json`, `bc4.json`, `bc5.json`, `bc7.json`: complete constant tables for all four modes (64-entry pair
  ranks, BC3 256-entry colour quadrant ranks, all 285 BC7 control codes, and the 255-entry dictionaries).
- `tests/modes.rs`: synthetic block and stream tests. The Rust CLI supports chunk decoding and mip 0 DDS export.
  The 16-byte Gfx10 tile patterns and mip-tail placement follow [ttpf-viewer at bafe9af](https://github.com/paryzius/ttpf-viewer/tree/bafe9afcaafd037232b2f32fdc19bf8a725f52bf/src).
  Export checks use synthetic stores. Retail mip 0 detiling parity for BC3/BC4/BC5/BC7 is unverified.

## Rules: exact

The rebuild rules are byte-identical to a reference decoder on every chunk of every store: BC4 77 chunks / 201,728
blocks, BC5 333 / 4,890,368, BC3 35 / 660,992, BC7 5,167 / 80,055,040; 0 differing blocks. Facts used: lane widths and
two symbols per lane for 16-byte blocks; index reference = lane 1, endpoint reference = lane 1 + unzigzag(lane 0);
references past the chunk start read a 255-entry dictionary; states and residual rules as described in the module docs.
In retail data BC1, BC3, BC4 and BC5 never use the index reference (lane 1 is always 0), so the index half of their
dictionaries is never read; BC7 uses both. Every BC7 dictionary entry is a single-subset state (`"subsets": 1`).

## How the tables were built

### Solved from retail data alone (`8b86a5e`)

| table | method | result against the reference |
|---|---|---|
| BC4, BC5, BC3-alpha pair ranks (64 each) | substitution cipher: bigram likelihood of the index symbols against pair patterns counted on the plain mips of the same textures; swap search plus exhaustive re-arrangement of 7-symbol subsets | 64/64 each. Smallest swap margin 722 (BC4), 3,618 (BC3), 77,134 nats (BC5) |
| BC7 control codes, modes 1, 3, 4, 5, 6, 7 (205) | rank order ((E+1)(O+1), E) of the 285 lane-15 pairs; mode from lane widths gives runs 7x64, 6, 5x4, 4x8, 3x64, 2x22, 1x64, 0x14, 2x42, 0x2; partitions descend inside a run and the anchor rule (0 top bits on blocks whose index chain is table-free) leaves exactly one assignment for modes 7, 3, 1; rotation from the wide lane; index selection from which index set is all zero when the scalar endpoints are equal | 205/205 |

The population matters for the cipher: counted on all plain blocks of a format instead of the same textures' mips,
BC4 comes out wrong in 47-64 symbols (BCPack BC4 is UI art).

### Remaining format constants filled (`c55c5fa` and `"subsets": 1` fix)

The remaining constant tables could not be pinned down exactly from retail statistics alone, and originally shipped as
`null` in `8b86a5e`:

- **BC7 control codes of modes 0 and 2 (80).** The anchor rule left 6 and 72 assignments; an index smoothness score
  across subset borders got 78 of 80 right (two mode-2 codes swapped, score margin 25).
- **BC3 colour quadrant ranks (256).** BCPack BC3 textures do not share the plain textures' pattern statistics (their
  most common quadrant is the complement of the plain one); edge continuity fixed the complement and got 199 of 256
  right.
- **Dictionaries, all four modes (255 entries each).** Blocks rooted at one entry are known up to that entry's values,
  and statistical fits on BC5 (neighbour equality, plain edge kernels, intra-chunk conditional edge kernels) got close
  (61/428 entry halves exact, 135 within 1, 52% of rooted half-blocks exact) without reaching exactness.

Commit `c55c5fa` filled these remaining constant tables from the format's tables as carried by a reference decoder
(keeping the data-solved entries unchanged, since they already matched). A follow-up fix set `"subsets": 1` on all 255
entries of `data/bc7.json` (which had been left as `null` in `c55c5fa`, causing multi-subset blocks referencing the
dictionary to increment `unfitted_blocks` even though their decoded bytes were already exact).

## Measured results

### With the current shipped tables (all 57 stores, checked against the reference decoder)

| mode | chunks | blocks | differing blocks | unfitted blocks | identical chunks |
|---|---|---|---|---|---|
| BC4 | 77 | 201,728 | 0 | 0 | 77 / 77 |
| BC5 | 333 | 4,890,368 | 0 | 0 | 333 / 333 |
| BC3 | 35 | 660,992 | 0 | 0 | 35 / 35 |
| BC7 | 5,167 | 80,055,040 | 0 | 0 | 5,167 / 5,167 |

Independent validation on issue #5 (`nineforge0`, 129 real chunks: 1 BC3, 100 BC5, 28 BC7; 651,264 blocks): 129/129
decode with 0 errors, 0 BC7 `unpack` rejections, `pack(unpack(b)) == b` on every block, `unknown_controls = 0`
(including 64,083 mode 0/2 blocks), and mip-downsampling MAE against plain mips matching the plain-only baseline (BC5
0.98 vs 0.61, BC7 1.54 vs 3.27, BC3 2.92 vs 3.75; zeroing dictionaries raises MAE to 10.4 for BC5 and 53.3 for BC7).

### Historical baseline: data-only tables before `c55c5fa`

Before the remaining constant tables were filled, with only the data-solved pair ranks and 205 BC7 control codes:

| mode | chunks | blocks | byte-identical blocks | flagged unfitted |
|---|---|---|---|---|
| BC4 | 77 | 201,728 | 52,049 (25.8 %) | 149,679 |
| BC5 | 333 | 4,890,368 | 628,322 (12.8 %) | 4,262,046 |
| BC3 | 35 | 660,992 | 173 | 660,992 |
| BC7 | 5,167 | 80,055,040 | 1,884,524 (2.4 %) | 78,170,905 |

Every block not flagged unfitted was already identical to the reference in BC4, BC5 and BC7.
